# DR-21 答案 · 反馈翻译：设计层用词 → 可检验的假设 → 最小 A/B

> 题面：[`60-casebook/drills/DR-21.md`](../DR-21.md) ｜ 对应案例：**G6**（主）；A4、A2、A3、A1、F2（参数层误读 = 代理指标）、F3（五句话其实是同几类病）、A5（原方案引入的换边风险）
> 训练技能：[`20-craft/screening-review/SKILL.md`](../../../20-craft/screening-review/SKILL.md)（反馈翻译协议）、[`20-craft/action-choreography/SKILL.md`](../../../20-craft/action-choreography/SKILL.md)、[`20-craft/storyboard-long-take/SKILL.md`](../../../20-craft/storyboard-long-take/SKILL.md)
> 翻译依据：[`00-orientation/glossary.md`](../../../00-orientation/glossary.md) B 表。

## 标准答案

### ①根因（分条）

**逐句：设计层释义，以及原方案的问题**

| # | 人类原话 | 设计层释义（人类在说什么） | 维度 / 病灶 | 原方案会造成的新问题 |
|---|---|---|---|---|
| ① | 「无电影级运镜」 | 镜头语言设计缺席：这一刻为什么用这个景别、从哪看、何时动、为什么动、在哪切。缺的是动机，不是动得少 | 镜头语言 / 1 分镜 | 固定镜头 = 0 是代理指标〔F2〕；`orbit` 与起始帧轴线冲突 → 左右乱〔A5①〕；一次生成多个运镜违反"一个主运镜"〔S-H3-10〕 |
| ② | 「苏晓冲击镜头过于耿直，没有运镜和合理的打斗逻辑」 | 两件事。**耿直**：直线冲、平铺记录，镜头不随拍点改变状态（推近时没在接触瞬间顿住，没有收束拉回）。**打斗逻辑**：因果链缺失，即她为什么此刻冲、神怎么应、空间怎么变、后果是什么 | 动作 + 镜头语言 / 1 动作设计 + 1 分镜 | 翻滚、旋身、回旋踢是空间拍，拍数越多空间越跳〔A5③；R4〕；招式数 ≠ 逻辑；环绕同①〔A4〕 |
| ③ | 「几乎没有做 BOSS 打斗」 | 打斗被"动作瞬间 + 反应镜头"的含蓄策略**替代**了，观众没看到一次交手（双方同框接触 + 反应 + 后果） | 动作 / 1 动作设计 | `epic, intense … lots of action` 是评价词，渲染不出来〔M3〕；镜头数从 3 加到 8 会造成碎镜〔A1〕 |
| ④ | 「全是几个简单动作的慢镜头」 | 全片没有速度层次，"慢"成了默认；时长被读成了事件速度，段内事件密度不够 | 节奏与速度 / 1 动作设计（节拍）+ 2 提示词 | `powerful, dynamic, large movement` 不改速度；动作幅度越大，肢体崩坏风险越高（这正是当初选含蓄策略的原因，A2） |
| ⑤ | 「片段式、剧情跳跃、无法理解」 | 叙事单位错了：一个动作一个镜号，没有"段"，因果链被切点切断，空间建立不起来 | 叙事 + 节奏 / 1 分镜 + 1 剧本 | 转场特效让切点更跳；开头加字卡解释是路由表明列的"不要做的事"〔[`00-orientation/production-lifecycle.md`](../../../00-orientation/production-lifecycle.md) §3〕 |

**共性根因**
1. **把设计层的词听成参数层的词**："运镜"被听成相机位移量，"打斗逻辑"被听成招式数，"慢"被听成动作幅度，"片段式"被听成转场不顺〔委托方实证·G6、A4、A2〕。
2. **每条方案都是"加数量"或"加形容词"**：两者都不改设计；数量是代理指标〔F2〕，形容词不渲染〔M3〕。
3. **五句话被当成五个独立问题**：其实是同几类病的五个样本，即动作设计缺席（②③④）、镜头语言缺席（①②）、段结构缺席（⑤，并加重④）。逐句打补丁永远修不完〔委托方实证·F3、G1〕。
4. **只给一种解释，不做验证**：含糊反馈至少有两种读法，猜一种直接做全片，猜错就再被打回一轮〔G6 回答〕。
5. **修在提示词层**：五句的病灶都在预制作阶段（分镜、动作设计、剧本）。

### ②修正方案（可直接执行）

**每句 2 个可检验假设 + 最小 A/B 样**。规则：只变一个量；同一起始帧、同一组 seed（每版 3 seed）；A、B 并排给人类，标签中性（"版本 1 / 版本 2"），顺序随机。

| # | 假设 | A（对照） | B（只变这一处） | 怎么判 |
|---|---|---|---|---|
| ① | H1 动机缺失：运镜和动作拍点脱钩 | 现版 | 单一推近，在刀接触时顿住（`the frame jolts as the blade hits`），后果时拉回 | 人类二选一；画面事实：接触帧 ±3 帧内镜头有响应（接触表可数） |
| ① | H2 景别序列缺失：全段同一景别 | 现版 | 重做起始帧：同一段按"全景起幅 → 中景 → 近景"排（视频提示词不变） | 人类二选一；数景别变化次数，每次变化能写出理由 |
| ② | H1 缺战术链（逻辑） | 直线冲刺 + 劈砍 | 同时长内：佯攻 → 神横扫落空 → 抓住收臂的空隙 → 劈中 → 后果 | 3 名冷观众复述"她为什么冲、神怎么应、结果如何"，B 的复述正确数 > A |
| ② | H2 镜头不随拍点变（耿直） | 同一动作，镜头匀速跟 | 同一动作：冲刺时推近，接触时顿住，后果时拉回（一个主运镜 + 事件式顿挫） | 人类二选一 |
| ③ | H1 缺交手回合 | 现版（瞬间 + 反应） | 一镜内完整交手：我攻 → 你挡 → 我变招，双方同框可见接触 | 画面事实：数双方同框的可见接触次数（A=0）；人类二选一 |
| ③ | H2 打击拍太稀、空间拍太多 | 3 次出招分散在走位中 | 原地密集攻防约 3s 内 6–9 拍，空间拍 ≤2〔外部调研·S-H3-09；学院立场 R4〕 | 接触表数命中拍数；人类二选一 |
| ④ | H1 缺实时速度约束 | 不写 `Real-time speed throughout, no slow motion` | 只加这一句 | 画面事实：从抬刀到接触的帧数（≤12 帧 ≈0.5s 记为实时）〔学院推断：0.5s 阈值待生产校准〕 |
| ④ | H2 事件密度不足（时长被读成速度） | 10s 段内 1 个动作 | 同 10s：3 拍 + 后果 + 静场（快 → 慢 → 爆 → 静）〔外部调研·S-H3-11〕 | 人类二选一；数段内状态改变次数 |
| ⑤ | H1 碎镜：没有段 | 现版剪辑（多个短镜） | 同内容合并为 8–15s、2–3 拍的长段；**在 animatic 阶段用关键帧验证**，不先送视频 | ≥3 名冷观众复述因果链，≥2/3 正确为过 |
| ⑤ | H2 剧本缺因果拍（缺动机或铺垫） | 现剧本 | 只加一个因果拍（例如她冲出前先看到神胸口的印记） | 冷观众复述"为什么"的正确率；animatic 即可测 |

**执行顺序**
1. 五句话先归并成三类病，在全片搜同类（列 SHOT 编号），写进 `review/defects.md`。
2. A/B 优先在最便宜的阶段做：⑤和②H1 用 animatic；①H2 用关键帧；其余用单段视频。不做全片。
3. 人类选定后，按选中的解释改**全片**同类，再全量回归。
4. **沉淀**：每组结果写一条记忆，格式按 [`40-memory/core-memory.md`](../../../40-memory/core-memory.md)，例如"「无电影级运镜」在本项目 = 接触瞬间无镜头响应（A/B 选 B）"；若出现术语表没有的新映射，补进 [`00-orientation/glossary.md`](../../../00-orientation/glossary.md) B 表；被人类点出而自查没发现的，写成新的找错题。

**附加技术假设（可选，第三假设）**：如果①的 B 版运镜仍然很弱，检查是否用了 4-step turbo、首帧脚手架句或背景参考板，这三者都会压制运镜幅度〔外部调研·S-H3-08〕。A/B：20 步 vs 4 步，其余不变。

## 打分规则（满分 10）

| 维度 | 满分 | 得分点 | 部分得分 |
|---|---|---|---|
| 根因 | 4 | **逐句释义 3 分**：每句 0.6，要求说到设计层（①动机 / 景别；②耿直 + 打斗逻辑两半都要答到；③含蓄策略替代了交手；④无速度层次 / 事件密度；⑤叙事单位 / 因果链）。**共性 1 分**：参数层误读（0.4）、五句归并为同几类病（0.4）、病灶在预制作（0.2） | ②只答了一半 → 该句 0.3；释义仍是参数（"运镜太少"）→ 该句 0 |
| 修正 | 4 | **假设与 A/B 3.5 分**：每句 0.7（两个假设各 0.35；每个必须写出固定什么、变什么、怎么判）。**沉淀 0.5 分**：写入记忆或术语表 + 应用到全片 | 假设不可检验（"让画面更有张力"）→ 该假设 0；A/B 同时变多个量 → 该假设减半 |
| 判据 | 2 | ①defects 表的翻译 + 假设必填（1）②禁止"数量 / 形容词"式方案，或 A/B 单变量规则（1） | — |

## 常见错答（扣分）

- **"问人类：您说的运镜具体指什么？"**：G6 的行为改变明确写了"不要问'您的意思是？'，而是给出 2 个可验证的解释，各做一个最小样让人类选"。
- **"②就是要更多招式"**：只读了字面"打斗"，没读出"逻辑"是因果链。
- **"④把动作写得更有力"**：形容词改不了速度；可数的是接触前的帧数。
- **A/B 直接做全片两版**：成本最高、变量太多，结果无法归因。修正最多 2 分。
- **五句各修各的**：没有归并，必然进入补丁式迭代。共性得分 0。

## 哪个脚本本可以拦下（原方案的副作用）

```bash
python3 50-rubrics/scripts/direction_audit.py season-01/ep03/video-prompts.md --storyboard season-01/ep03/storyboard.md   # ①② 的 orbit / 环绕 → DIR-camera
python3 50-rubrics/scripts/segment_rhythm.py season-01/ep03/storyboard.md                                                 # ② 拍数增加 → A5-beats-many；③⑤ 镜头变碎 → A1-*
python3 50-rubrics/scripts/prompt_lint.py season-01/ep03/video-prompts.md --anchors season-01/ep03/anchors.md --storyboard season-01/ep03/storyboard.md   # ③ epic → VP-adjective；④ 缺实时句 → VP-realtime
```

- **脚本盲区**：脚本只能拦原方案的副作用。"翻译对不对"没有任何脚本能判，只能靠 A/B 让人类选，再由冷观众复述验证。`VP-adjective` 的词表含 `epic`，不含 `intense / powerful / dynamic`，这些词要靠目视判据拦。

## → 装载后的行为改变

- 下次收到含糊反馈，**先**查术语表翻译到设计层，**再**写 2 个可检验假设，各做一个单变量最小 A/B；禁止反问"您的意思是？"，禁止把它变成数量或形容词。
- 下次同时收到多条反馈，**先**归并成几类病并在全片搜同类，**再**动手。
- 下次 A/B 有结果，**当轮**写入记忆并应用到全片。
