# DR-14 答案 · 槽位顺序与改号残留：校验通过 ≠ 修对了

> 题面：[`60-casebook/drills/DR-14.md`](../DR-14.md) ｜ 对应案例：**E1**、**E2**（主）；T-3（起始帧顺序 1）、P4、F2（校验通过当正确）、B1（错参考引起漂移）
> 训练技能：[`20-craft/video-prompting-h3/SKILL.md`](../../../20-craft/video-prompting-h3/SKILL.md)、[`20-craft/edit-and-assemble/SKILL.md`](../../../20-craft/edit-and-assemble/SKILL.md)、[`20-craft/production-director/SKILL.md`](../../../20-craft/production-director/SKILL.md)

## 标准答案

### ①根因（分条）

**A. 参考槽（周二）**
1. **占位槽排在顺序 1**：删掉占位后，剩下的槽从 2 起，不连续，18 镜一起失败〔委托方实证·E1〕。
2. **只改了 references 的编号，没改 `<Picture N>`**：重编号后，`<Picture 2>` 指向上一镜的关键帧 REF-SHOT004-START，而它在 [S1] 定义里是**角色身份参考**；`<Picture 3>` 已经不存在。绑定校验只查编号是否连续，不查图指得对不对。所以"通过"是假通过，18 镜是带着错的身份参考生成的〔委托方实证·E1、T-2（`<Picture N>` 编号与引用顺序一致）；B1 风险〕。
3. **校验时机太晚**：槽位顺序在 run 时才被 ComfyUI 拦下，没在 prepare 里模拟"删掉占位之后的样子"〔委托方实证·P6、T-3〕。
4. **起始帧产出后没把它提回顺序 1**：E1 的修正规则是"占位放末位，升格时再提回顺序 1"。日志写"references 保持现状"〔委托方实证·E1、T-3〕。

**B. 集号顺延（周四）**
5. **按升序依次全局替换，结果连环串改**：先把 ep01 换成 ep02，下一步 ep02→ep03 会把刚换出来的那批也一起换掉，最后原 ep01、ep02 的引用全部变成 ep04。目录改名按降序做对了，文档替换却按升序做〔学院推断：可在文档副本上复现；验证法：对替换前的版本按同样顺序重放，统计 ep04 出现次数〕。
6. **只修报错的那 22 条**：渲染校验只拦"文件不存在"。被换成"另一集里恰好存在的同名文件"的路径不会报错，比如 CUT-002 的前情提要现在可能指向 ep04（未来剧集）的结尾〔委托方实证·E2〕。
7. **手工替换，没有预演，也没做全量复查**：编辑器把行尾改成了 CRLF（git diff 显示整文件都变了），这个信号被当成"显示问题"忽略。E2 的修正要求是"二进制级替换，行尾零扰动 + 全仓 grep 复查 + 重渲"〔委托方实证·E2〕。

**方法论（两件事的共同病根）**
8. **把"校验器不报错"当成"修对了"**：绑定校验通过、渲染 0 报错，都只证明"格式合法、文件存在"，不证明"指向的是对的东西"。这是 F2 代理指标在工程层的样子〔委托方实证·F2〕。改完之后没有任何一步去看产出（身份参考对不对、前情提要放的是不是上一集）。

### ②修正方案（可直接执行）

**A. 参考槽**
1. 暂停 SHOT-005…SHOT-022 已生成镜头的验收。逐镜跑 `contact_sheet.py <clip> --keyframe <REF-SHOTnnn-START>`，对照角色板核身份。用错身份参考生成的镜，一律重出。
2. 预制作期统一改成"其余参考 1..N-1 + 占位 N"，`<Picture N>` 同步改：
   ```markdown
   - references: 1=CHR-SUXIAO-BOARD; 2=REF-SHOT004-START; 3=REF-SHOT005-START-PLACEHOLDER
   subject_definitions:  [S1] … <CHR-SUXIAO 锚点句逐字> <Picture 1>
   retention_analysis:   Background, light and the broken pillar follow <Picture 2>.
   ```
   提示词里不得出现指向占位槽的 `<Picture 3>`。删掉占位后剩 1、2，天然连续。
3. 起始帧产出后升格：把本镜起始帧提回顺序 1，**其余编号与全部 `<Picture N>` 同步 +1**，然后重跑下面的检查。
4. 槽位检查前移到 prepare：每次改 references 或导出绑定，都跑 `slot_order_check.py --simulate-remove-placeholder` 和 `prompt_lint.py`（`VP-picture`）；有绑定 JSON 时加 `--bindings`。

**B. 集号顺延**
5. 用 git 把三份文档恢复到替换前的版本。
6. 用工具按**降序**改名，每步先预演再写盘：
   ```bash
   python3 50-rubrics/scripts/asset_exists.py season-01/ --rename ep03 ep04          # 预演，看逐文件次数与示例行
   python3 50-rubrics/scripts/asset_exists.py season-01/ --rename ep03 ep04 --apply
   # 然后 ep02→ep03，最后 ep01→ep02，同样先预演后 --apply
   ```
7. 每集单独查"引用了不该引用的集号"：在 ep02 里，ep03、ep04 都不该出现；在 ep03 里，ep04 不该出现。前情提要这类合法的跨集引用逐条人工确认。
8. 行尾恢复 LF；重新渲染；把**所有路径被改过的 CUT** 抽首尾帧目视，确认画面属于正确的集（CUT-002 重点看）。

## 常见错答（扣分）

- **"重编号后校验通过了，问题解决"**：本题的核心陷阱。根因②不得分。
- **"写个脚本把 22 条手改的都改对"**：还是只修报错的那几条，存在但指错的路径漏掉。
- **"git diff 整文件变化是显示问题"**：那是行尾被改成了 CRLF，E2 明确要求行尾零扰动。
- **"以后不要用占位槽"**：占位槽本身没错，错在位置。E1 给的是"放末位"的工序，不是禁用。

## 哪个脚本本可以拦下

```bash
python3 50-rubrics/scripts/slot_order_check.py season-01/ep02/video-prompts.md --simulate-remove-placeholder --assets-dir season-01/ep02/assets
python3 50-rubrics/scripts/prompt_lint.py season-01/ep02/video-prompts.md --anchors season-01/ep02/anchors.md --storyboard season-01/ep02/storyboard.md
python3 50-rubrics/scripts/asset_exists.py season-01/ep03/ --stale-token ep04
```

- 预制作版应报 `SLOT-placeholder-pos` 和 `SLOT-sim`（删掉占位后从 2 起），在 run 之前就拦下。
- 重编号版：`slot_order_check` 会通过（编号连续）。这正是**脚本盲区**。能拦住它的是 `prompt_lint` 的 `VP-picture`：`<Picture 3>` 未定义（error），`1` 号从未被引用（warn）。所以改槽位后两个脚本都要跑。
- `asset_exists --stale-token ep04` 对新 ep03 里指向 ep04 的路径报 `E2-stale-path`，**路径存在也报**；同时报 `E2-crlf`。

## → 装载后的行为改变

- 下次放占位槽，**一律放末位**；改 references 时，同一次编辑里同步改 `<Picture N>`，再跑两个脚本。
- 下次改集号，**禁止**用编辑器全局替换；先 git 留快照，再用工具降序预演、写盘，然后按集扫描越界集号。
- 下次校验器说"通过"，**还要**去看产出（身份参考、跨集引用）是不是对的东西。
