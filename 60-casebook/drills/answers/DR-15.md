# DR-15 答案 · 环境怪癖与"提示词 ≠ 产出"：把自己的流程错误记成"环境不稳定"

> 题面：[`60-casebook/drills/DR-15.md`](../DR-15.md) ｜ 对应案例：**E3**（E3-1、E3-2、E3-3）、**E4**（主）；P5（链式参考）、D3（随机 vs 结构性）、A5④（指令矛盾）
> 训练技能：[`20-craft/production-director/SKILL.md`](../../../20-craft/production-director/SKILL.md)、[`20-craft/keyframe-freeze/SKILL.md`](../../../20-craft/keyframe-freeze/SKILL.md)、[`20-craft/shot-qc/SKILL.md`](../../../20-craft/shot-qc/SKILL.md)

## 标准答案

### ①根因（分条）

**直接原因**
1. **[09:10] 中文路径加 cmd 裸跑多行中文命令，输出被吞**〔委托方实证·E3-1〕。"终端无输出"被当成了"没有超容量的镜"，没有证据被当成了"通过"的证据。这一步实际上什么都没检查。
2. **[09:40–10:00] 长任务放在前台跑，被终端的 10 分钟超时掐断**〔委托方实证·E3-2〕。终端超时 ≠ 生成失败：ComfyUI 服务端的任务还在跑。重复提交两次，队列里堆了 18 个任务，GPU 花掉 3 倍；同名序列文件分不清来源，"取最新的一个"又切断了"提示词 / seed → 文件"的对应关系，验收无从追溯。
3. **[11:40] 技能改完没重启运行时**〔委托方实证·E3-3〕。技能清单是装配期一次性扫描的，改了不重启就不生效；技能正文其实可以直接读取使用。"没出现在提示词里"被归因成"规则无效"，还把一条正确的规则回滚掉了。
4. **[13:00] 产出和提示词不一致，没回写就采用**〔委托方实证·E4〕。提示词写的是 `short … for a moment, then is gone`，产出是"一路延伸到画面 2/3 再渐隐"。这张产出直接被当成参考图送进 SHOT-013，而 013 的提示词还写着"短"。参考图和提示词说的是两件事，模型只能在两者之间摇摆〔委托方实证·E4、A5④（指令打架模型就乱编）〕。

**方法论原因**
5. **用终端回显判断成败**：成败只能看"退出码 + 预期产物存在且非空"，不能看屏幕上有没有字〔委托方实证·E3 判据〕。09:10、09:50、11:40 三处误判都出在这里。
6. **把结构性缺陷当随机缺陷**：SHOT-013 衔接不上，是指令矛盾造成的，抽多少 seed 都一样。继续抽 6–9 就是"换 seed 碰运气"〔委托方实证·D3、F3〕。
7. **归因到环境，下一天会照样重犯**：日报写"环境不稳定"，没写任何一条流程修正，明天会原样重犯这四个错。

### ②修正方案（可直接执行）

1. **先清现场（第二天开工前）**：
   - `GET /queue` 查出重复任务，用 `/queue` 管理接口删掉多余的；用 `GET /history/{prompt_id}` 把每个输出文件对回它的提交（提示词版本、seed）〔外部调研·S-COMFY-10〕；
   - 建一张 `prompt_id | SHOT | seed | 输出文件` 对照表；对不上来源的文件归档，不参与验收；SHOT-012…017 用对照表上的文件重新走 QC。
2. **路径与执行方式**：项目目录改成英文 kebab-case（例如 `D:\drama\season-01\ep03\`），文件名也一样〔CONVENTIONS §1.6；E3-1〕；所有检查都用 `.py` 脚本文件执行，09:10 那一步换成学院脚本重跑：
   ```bash
   python 50-rubrics/scripts/dialogue_capacity.py --storyboard season-01/ep03/storyboard.md --prompts season-01/ep03/video-prompts.md --json > qc/dialogue_capacity.json
   ```
   成败看退出码（0/1/2）和 `qc/dialogue_capacity.json` 是否非空。
3. **长任务改成异步**：H3 生成走 `POST /prompt` 提交，把返回的 `prompt_id` 记进日志，轮询 `/history/{prompt_id}` 取产物；预计超过 5 分钟的任务一律放后台或走 API〔E3-2；S-COMFY-10〕。重投之前先查 `/queue` 和 `/history`。
4. **技能改动**：恢复那条实时速度句的修改 → 重启运行时 → 确认技能清单里能看到新版本；看不到就直接读 `SKILL.md` 正文照做。规则本身用 `prompt_lint.py` 兜底：动作镜缺实时速度句时报 `VP-realtime`（error），不依赖技能有没有加载。
5. **SHOT-012 / 013 回写并统一事实**：二选一，写进 `qc/SHOT-012.md`：
   - 接受 seed 2：把提示词回写成产出的事实，例如 `a thin vertical line of light shoots up from the mark, reaching about two-thirds of the frame height, then fades out`，标记"已回写"；SHOT-013 用同一句描述；
   - 或者拒绝 seed 2：从 013 的 references 里撤掉 REF-SHOT012-END，012 按原提示词重抽。
   两条路选哪条都行，但都要**停止抽 SHOT-013 的 seed 6–9**，先统一事实再生成。
6. **日报重写**：列出 4 条流程错误、各自的修正，以及已浪费的 GPU 时长。

## 常见错答（扣分）

- **"把超时调长就好"**：生成要几十分钟到几小时，调长超时治不了本；关键是异步提交，并在重投前查队列。
- **"SHOT-013 多抽几个 seed 总能对上"**：指令矛盾是结构性的。修正⑤不得分。
- **"技能规则无效，以后都写进提示词模板"**：方向对了一半（规则应该固化到模板和 lint 里），但没指出"不重启不生效"这个根因，根因③不得分。
- **"中文路径是 Windows 的锅"**：E3-1 的修法是改成英文路径、用 .py 文件执行，不是换系统。

## 哪个脚本本可以拦下

```bash
python 50-rubrics/scripts/dialogue_capacity.py --storyboard season-01/ep03/storyboard.md --prompts season-01/ep03/video-prompts.md --json
python 50-rubrics/scripts/prompt_lint.py season-01/ep03/video-prompts.md --anchors season-01/ep03/anchors.md --storyboard season-01/ep03/storyboard.md
python 50-rubrics/scripts/contact_sheet.py season-01/ep03/assets/clips/SHOT-012.mp4 --keyframe season-01/ep03/assets/keyframes/REF-SHOT012-START.png --out-dir qc/SHOT-012
python 50-rubrics/scripts/run_all_selftests.py --quick
```

- `dialogue_capacity.py` 取代 09:10 的手写一行命令；学院脚本的输出在非 UTF-8 控制台下会把无法编码的字符替换成 `?`，不会崩溃。`run_all_selftests.py --quick` 用来确认工具在这个控制台里真的能跑、能输出。
- `prompt_lint.py` 的 `VP-realtime` 不依赖技能有没有加载，能独立拦下"实时速度句缺失"。
- **脚本盲区**：E4 的"提示词 ↔ 产出"不一致没有自动检查，只能靠接触表目视，再按判据回写；超时和重复提交靠流程纪律（`prompt_id` 日志），脚本拦不住。

## → 装载后的行为改变

- 下次任何检查"没有输出"，**一律当成失败**，先查退出码和产物文件；禁止把沉默当通过。
- 下次提交超过 5 分钟的任务，**先**记 `prompt_id` 走异步；重投之前**必须**查队列和 history。
- 下次采用的产出与提示词不一致，**先**回写或拒绝，**再**决定它能不能进参考链；同一镜衔接不上时，先查指令矛盾，不抽 seed。
