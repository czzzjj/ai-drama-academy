# DR-17 答案 · 代理指标：把"运镜"翻译成相机位移计数

> 题面：[`60-casebook/drills/DR-17.md`](../DR-17.md) ｜ 对应案例：**F2**（主）；A4（运镜脱钩）、A5（换边词搅乱轴线）、G6（反馈理解偏差）、F3（加指标 = 打地鼠）
> 训练技能：[`20-craft/storyboard-long-take/SKILL.md`](../../../20-craft/storyboard-long-take/SKILL.md)、[`20-craft/screening-review/SKILL.md`](../../../20-craft/screening-review/SKILL.md)、[`20-craft/video-prompting-h3/SKILL.md`](../../../20-craft/video-prompting-h3/SKILL.md)

## 标准答案

### ①根因（分条）

**直接原因**
1. **把代理指标当成了质量本身**：固定镜头占比、运镜词数、primitives 覆盖、光流强度，都是"能数"的量，不是观众看到的"镜头语言"。指标一旦成为目标，就会以最省力的方式被满足，也就是每镜多塞几个运动词〔委托方实证·F2、A4①〕。
2. **反馈被翻译到了参数层**：人类说的「无电影级运镜」指的是镜头语言设计，即这一刻用什么景别、从哪看、何时动、为什么动、在哪切。agent 听成了"相机动得不够多"〔委托方实证·G6、A4；[`00-orientation/glossary.md`](../../../00-orientation/glossary.md) B 表〕。
3. **SHOT-011 左右对调是看板直接造成的**：`orbit around`、`whip pan`、`arc right` 都是左右维度的运动，和起始帧钉死的"神在左 / 苏晓在右"冲突。轴线由起始帧决定，文字改不动；文字和起始帧打架时，模型就把空间搅乱〔委托方实证·A5①、M4〕。
4. **一次生成塞了 2–3 个运镜**：`dolly in, then arc right, then crane up`。H3 一次生成只能有一个主运镜，运镜是全局的，不能分段指定〔外部调研·S-H3-10、S-H3-09；学院立场 [`00-orientation/evidence-reconciliation.md`](../../../00-orientation/evidence-reconciliation.md) R5〕。

**方法论原因**
5. **替代指标也退化成了代理**：三条因果句（"苏晓行动 / 气氛紧张 / BOSS 很强大"）句式都合格，所以 `A4-cause` 0 error，但 X 都不是画面里某一刻发生的具体事件，Y 也没落在那一刻。句式存在 ≠ 因果存在〔委托方实证·A4；F2 根因 7〕。
6. **光流强度上升 = 画面更晃，不等于更"电影"**：这是把"运动量"当"运动设计"；越优化，晃动和空间跳变越多。〔学院推断：验证法——取 v1/v2 同一段，给 3 名冷观众看，问"两人谁在左"和"刀砍中了哪里"，比较正确率。〕
7. **指标没有登记"它证明不了什么"**：每个数字只有"通过"语义，所以全绿就被读成"好了"；v2 失败后，结论是"指标不够全"，下一步又去加指标，这是 [`00-orientation/production-lifecycle.md`](../../../00-orientation/production-lifecycle.md) §3 明列的"不要做的事：再加一个技术指标"〔委托方实证·F2、F3〕。
8. **验收不看片**：v2 的"达标"完全来自看板，没有一次按观众方式看这三镜。观众判断的顺序是情绪 > 故事 > 节奏 > 视线 > 2D > 3D，看板上全是最末端的东西〔外部调研·S-STORY-13〕。

### ②修正方案（可直接执行）

1. **停掉 v3 计划**；看板改成"指标登记表"：每个指标写一列"证明什么 / 证明不了什么"，全部归到 L0 下限，禁止在报告里拿它们证明运镜质量。
2. **回到分镜层，重做镜头语言设计**（每段一张小表，不是每镜一个运动词）：
   - 景别序列：SHOT-010 全景起幅（交代神的体量与两人距离）→ 推近；SHOT-011 中景；SHOT-012 近景苏晓 → 拉回。每一次景别变化都写理由；
   - 每次生成**一个**主运镜，只在高度 / 距离维度上动（推、拉、升、降），**删掉** orbit / arc / whip pan / truck〔M4、R5〕；
   - 镜头对动作的响应写成事件：`the frame jolts as the blade hits the stone shin`，不写成第二条运镜指令〔R5〕；
   - 起幅放在主体最大的那一端："A shot that must end tight has to open wide"〔外部调研·S-H3-08〕。
3. **因果句写到具体事件和时刻**：例如 SHOT-010 `因为 4 秒左右刀砍中石胫，所以推近在接触瞬间顿住，把力量交给碎石`；SHOT-012 `因为苏晓抬头盯住神，所以镜头从她的近景拉回，让神的体量重新进画`。X 必须能在 `内容` 列里找到。
4. **跑审计**：`direction_audit.py` 必须 0 个 `DIR-camera`；SHOT-011 以 `神=LEFT; 苏晓=RIGHT` 重出起始帧和视频。
5. **用看片验收，不用看板**：三镜生成后 1 倍速连续看；再和 v1 并排对照（交换顺序各看一次）；回答三个问题：每次运动能不能说出为什么、接触瞬间镜头有没有响应、两人谁在哪一眼可读。
6. **含义不确定时做 A/B**：同一段出两版（A：推近 + 接触顿挫；B：固定全景 + 剪辑切近景），交人类选，结果写入记忆〔G6〕。

## 常见错答（扣分）

- **"多样性指数设计得不好，换个更好的指标"**：还是在加指标。根因⑤不得分。
- **"把 whip pan 换成 truck left"**：换汤不换药，还是左右维度，A5 照样复发。
- **"因果句已经 100% 覆盖了"**：句式合格不等于因果成立，`A4-cause` 只查句式。
- **"运镜问题只在 SHOT-011"**：SHOT-010 的三段运镜、SHOT-012 的 dutch angle + 空洞因果句都是同一个病。只修点 → 修正最多 2 分。

## 哪个脚本本可以拦下

```bash
python3 50-rubrics/scripts/direction_audit.py season-01/ep03/video-prompts.md --storyboard season-01/ep03/storyboard.md
python3 50-rubrics/scripts/segment_rhythm.py season-01/ep03/storyboard.md
```

- `direction_audit.py` 会对分镜 `运镜` 列和提示词中的 `arc` / `orbit` / `whip pan` 报 `DIR-camera`（单轴定侧下为 error），在 v2 生成之前就能拦下左右对调。题面中的分镜表也可以直接作为 `--storyboard` 输入。
- **脚本盲区**：`segment_rhythm.py` 对这三条空洞因果句**不会**报 `A4-cause`，因为它只查"因为 X，所以 Y"的句式。看板上的"100%"就来自这里。因果是否成立只能目视。

## → 装载后的行为改变

- 下次收到「无电影级运镜」一类反馈，**先**查术语表翻译到设计层（景别、视点、何时动、为何动、在哪切），**禁止**把它变成运动计数。
- 下次想加一个指标来证明质量，**先**写下"它证明不了什么"；证明不了观感的，只能当下限。
- 下次写运镜，一次生成只写一个高度 / 距离维度的主运镜，因果句的 X 必须是画面里某一刻真实发生的事件。
