# C2 · 验收放水（早期误判）

> 一句话：**"通过"是一个需要证据的结论，不是一种感觉。** 没有裁剪图的"通过"，在本学院里一律等于"未验证"。

## 症状（含人类主创原话，逐字引用档案）

- 同一批板图，第一次验收判"通过"，复验时发现"黑臂对比不足"是硬伤〔委托方实证·C2〕。
- 委托方 agent 的自我诊断（档案原文）："自己的验收标准执行不严，早期误判放行"〔委托方实证·C2〕。这是 agent 的话，不是人类主创的原话。
- 对应子案 C1-7「尼加狄 v2 前」：方位对了，但黑臂对比弱，被早期验收放行；复核查出后重写提示词，最后由人类主创选定新版〔委托方实证·C1-7〕。
- 档案没有保留人类主创关于本案的「」逐字原话。

## 现场（何时、哪一集/哪一轮、具体到镜/字样/数字）

- 对象：BOSS 尼加狄的板图批次，属于高风险资产。
- 标准本身没错：锚点卡要求黑臂，也要求方位正确。错在**执行**：第一次验收确认了"方位对"，这正是上一轮 C1-6 修过的那一项；但没有确认"对比是否一眼可读"。
- 错误是靠复验/复核，也就是第二遍检查拦下的。这说明第二遍有效，但当时第二遍不是制度，是偶然。
- 档案**没有记录**：第一次验收用什么形式记录、看图时多大尺寸、复验隔了多久、复验者是不是同一个会话。

## 根因（分条；区分"直接原因"与"方法论原因"）

### 直接原因
1. 验收方式是"看一眼差不多"，不是"逐特征放大核验"〔委托方实证·C2〕。
2. 没有独立复验环节〔委托方实证·C2〕。

### 方法论原因
3. **验收记录只有结论，没有证据**。只写"通过"两个字，第二个人无法复查，错误就失去了被发现的机会。委托方事后定下的判据正是"必须留下逐特征核验证据"〔委托方实证·C2〕。
4. **刚修好的那一项吸走了全部注意力**。C1-6 修的是方位，所以 v2 验收时重心落在"方位对不对"，对比度这个独立属性被顺手放过。〔学院推断；**验证方法**：回看当时的验收记录，看是否逐条列出了锚点卡的每一项；今后用逐条表格强制全覆盖。〕
5. **"有"和"够"被混为一谈**。存在性检查过了（有没有黑臂），不代表程度检查过了（对比够不够、一眼能不能读出）。程度属性必须在观看条件下判断，不能在原图放大状态下判断。
6. 与 F1 同一个结构：生成者就是验收者，同一个会话的盲区是一致的〔委托方实证·F1〕。

### 外部调研补强的根因
7. 审查应优先交给没有参与当前版本创作的 reviewer；自检必须如实声明是自检。每条 finding 要写位置、证据、影响、严重度。无法读取媒体时，不能从文字去推断脸是否一致之类的结论〔外部调研·S-ZEN-12〕。
8. 验收要有真实证据包，四道门逐道过；没直接检查的项，只能标"未验证"〔外部调研·S-PIPE-01〕。
9. 返工的常见原因之一是"版本和执行状态冒充内容权威"〔外部调研·S-ZEN-23〕。"已经跑完、已经出图"不等于"已经过关"。
10. 只靠 VLM 打分不可靠，要把大模型的语义判断、专家模型的测量和人评校准结合起来〔外部调研·S-PIPE-12〕。agent 用视觉能力看图也一样，需要测量型证据来补强：裁剪、并排、缩略、去色。

## 修正过程（做了什么、第几轮、结果）

- 委托方的修正：高风险资产（BOSS、主角、核心道具）一律用"裁剪特写 + 与板图并排压图对照"的方式验收；重要资产增加"第二遍复验"〔委托方实证·C2〕。
- 结果：C1-7 的弱对比在复核中被查出，重写提示词后人类主创选定新版〔委托方实证·C1-7〕。
- 学院把它固化成格式：验收记录按 [`70-playbooks/format-contracts.md`](../../70-playbooks/format-contracts.md) §6 写，包含结论、证据文件、逐项表，高风险资产必填复验人。
- 学院补充的证据路径写法：证据要写成 Markdown 链接，或带目录的反引号路径（如 `qc/BOSS-NJD/crop-arm.png`），`asset_exists.py` 才能校验到。裸路径只有加 `--bare` 时才报 warn。

## 可固化判据（每条标 [自动]/[目视]/[冷观众]；被 50-rubrics 引用）

- [目视] 验收记录不能只是一句"通过"。`qc/<ID>.md` 必须包含：结论（通过 / 不通过 / 有条件通过）、证据文件列表、逐项表（锚点卡的每条 `必现` / `禁用` / `方位属性` 各占一行）〔C2；format-contracts §6〕。
- [自动] 验收记录引用的证据图（裁剪图、对照图、接触表）真实存在且非空。用 `asset_exists.py qc/` 检查，报 `E2-missing-asset` 或 `E2-empty-asset` 即不通过〔C2、E2〕。
- [目视] 高风险资产（BOSS、主角、核心道具）每条特征配一张裁剪特写，外加一张与板图的并排对照图〔C2〕。静帧用 ffmpeg `crop` + `scale=…:flags=neighbor` 放大，用 `hstack` 并排；视频用 `contact_sheet.py <clip> --crop 名=X:Y:W:H`。
- [目视] 程度属性（对比、大小、数量）按观看尺寸判：缩到 270 宽并去色后仍然可读〔C1-7〕。
- [目视] 高风险资产的第二遍复验由**独立会话**完成，只给它看图和锚点卡，不给生成提示词，也不给作者的通过理由。`复验人` 一栏填会话标识和日期〔C2；S-ZEN-12〕。
- [目视] 没亲眼核过的项，在逐项表里写"未验证"，**禁止**打"✅"〔S-PIPE-01〕。
- [目视] 复验发现首验漏判时，把漏掉的属性补进逐项表作为必查项，并写成新的找错题回流题库（F4 训练回路）。

## → 行为改变（下次……）

- 下次写验收结论前，先把锚点卡的每一条抄成逐项表，每行附一张裁剪图。表没填满，不写结论。
- 下次验收刚修过的资产时，**不要从修过的那一项开始**，从逐项表第一行开始全量重核。
- 下次高风险资产过关后，开一个独立会话做第二遍复验。复验没做之前，结论只能写"有条件通过（待复验）"，不得放行到下一阶段。
- 下次遇到"对比、大小"类要求，先缩到观看尺寸再判，不在原图放大状态下判断"够不够"。
- 下次被人类或复验指出漏判，先补判据，再改图。
- 下次在交付报告里，把"未验证"项原样列出，不能省略（同 [`50-rubrics/definition-of-done.md`](../../50-rubrics/definition-of-done.md) 的交付声明规则）。

## 适用面与迁移（★通用 / ☆项目特有；换题材/换模型时是否仍成立）

- ★ 适用于板图、关键帧、视频、成片任何一层的验收；换模型、换题材都成立。
- ★ 资产变多时的做法：按风险分级。高风险资产全量放大 + 独立复验；普通资产逐项表 + 抽检。**不允许**因为量大而整体降级成"看一眼"。
- ★ 同一结构会在成片层重演（F1、F2）：技术闸门全绿就当"通过"。本卡的"结论必须附证据"同样适用于成片报告。
- ☆ 黑臂对比这一具体属性属于本项目。
