# 装机验证（Install Verification）

> 回答 G3〔委托方实证·F4〕"学了一堆技能，能力没有质变"：本文件是**学院自己的验收任务**——让一个从未学过短剧的 agent 会话装载学院，完成一个 15 秒 BOSS 战段落的设计与提示词，再用**脚本 + 评审会话**打 100 分；同一任务、同一模型、**不装学院**再做一遍作对照。≥70 分才算"装机验证通过"。
> 它只证明：装载学院后，agent 在**设计与提示词层面**（L0 可核证据 + 评审判断）的行为变了。它**不**证明成片好看、观众想追（那是 L1–L3，见 [`90-curriculum/cold-audience-protocol.md`](cold-audience-protocol.md)）。分数是〔学院推断〕的校准量，不是质量担保。
> 读者分两类：**受测 agent 只读 §2**（任务包，由运行者粘贴给它，不要让它读本文件其余部分）；**运行者与评审只读 §3 起**。受测 agent 若已读过 §3 之后的内容 = 本次无效，换 §3.4 的变体重测。

## 2. 受测任务包（运行者整段粘贴给受测 agent；其中不得夹带 §3 之后的内容）

````text
【任务：15 秒 BOSS 战段落】
你要为一部竖屏 9:16 AI 短剧做一段约 15 秒的 BOSS 战的预制作与提示词。
生成工具：MiniMax H3（图/参考图 → 视频，9:16，音画同轨）；关键帧用 Qwen-Image 出图（本任务不真正出图，起始帧以文字声明为准）。
不涉及剧集上下文，所有角色为本任务原创，无需考证原著。

【本段内容（逐字，不得改设定）】
地点：清晨林间空地，薄雾，地面湿滑长满青苔；空地尽头是一扇石门。
角色 A「女剑士」：二十岁出头，短发，灰色旅行斗篷，单手持一柄窄刃直剑。
角色 B「石守卫」：约四米高的苔藓覆盖石像，胸口有一道旧裂缝，右肘关节有一条细裂纹；只会一种攻击：抡起右拳重砸地面，砸出后需要一点时间才能抽回。
起始状态：女剑士在画面左侧，石守卫在画面右侧，相距约八米，守卫挡在她与石门之间。
女剑士想要：越过守卫，到达石门。
阻碍：守卫不让路，且体量与力量远超她，正面硬接必败。
本段发生且只发生：一个交手回合（女剑士引它出手 → 它出手 → 她利用这一击的代价反击）。
本段结束时必须成立的画面事实：①石守卫的右前臂在肘部断裂坠地；②守卫向后踉跄退出一步；③守卫胸口裂缝里透出一丝红光（本段末尾的悬念：红光是什么）。
对白（全段只有这一句，由女剑士说，逐字使用，不得改字）：「你的拳头，比我的剑慢。」石守卫不说话。
总时长：整段各镜时长之和在 13.5 秒到 15.0 秒之间；镜头数自定（每个镜头都会单独送 H3 生成）。

【交付物（放进目录 verification/run-01/）】
1. storyboard.md —— 先写「段结构」表，再写「分镜表」。
2. action-design.md —— 战术链表（环数自定）、动作的逐相写法、事件时长表（每个事件占多少秒，并说明依据）。
3. anchors.md —— 两个角色的最小锚点卡。
4. video-prompts.md —— 每镜一个提示词，采用 H3 的 Ref2VA 模式。
5. self-check-report.md —— 自检报告：运行下列五个脚本并粘贴真实输出与退出码；逐条处置每个 error/warn；写你对本段的交付声明（达到什么级别、哪些没验证）。
   若你的环境里没有这些脚本，就在报告里写「未运行：环境中无此脚本」，不要编造输出。
   脚本（$ACADEMY_HOME 为学院根目录；没有学院则不适用）：
   python3 $ACADEMY_HOME/50-rubrics/scripts/segment_rhythm.py verification/run-01/storyboard.md
   python3 $ACADEMY_HOME/50-rubrics/scripts/dialogue_capacity.py --storyboard verification/run-01/storyboard.md --prompts verification/run-01/video-prompts.md
   python3 $ACADEMY_HOME/50-rubrics/scripts/h3_frame_grid.py --check verification/run-01/video-prompts.md
   python3 $ACADEMY_HOME/50-rubrics/scripts/prompt_lint.py verification/run-01/video-prompts.md --anchors verification/run-01/anchors.md --storyboard verification/run-01/storyboard.md
   python3 $ACADEMY_HOME/50-rubrics/scripts/direction_audit.py verification/run-01/video-prompts.md --storyboard verification/run-01/storyboard.md
   报告里任何事实性断言（数字、规则、来源）要写依据；不确定的写「推断」并写出怎么验证。

【文件格式（只给形状，不给约束）】
- 分镜表表头逐字：段号 | 镜号 | 时长(s) | 拍数 | 内容 | 运镜 | 运镜因果 | 起始帧方位 | 对白 | 短镜理由
  对白多句用「 / 」分隔，每句「说话人：台词」；无对白写「—」。起始帧方位写法「名=LEFT; 名=RIGHT」（取值 LEFT/RIGHT/CENTER/FG/BG）。无短镜理由写「—」。
- 视频提示词：每镜一个二级标题「## SHOT-001」，其下是元数据列表（- 时长: / - 帧数: / - 模式: / - first_frame: / - references: / - 起始帧方位: / - 轴线策略: / - 锚点: / - 角色映射:），
  再跟一个 ```h3 代码块；Ref2VA 的六段各顶格起行：subject_definitions: / summary: / retention_analysis: / detailed_description: / overall_soundscape: / non_diegetic_music:
- 锚点卡：每个资产一个二级标题「## ANCHOR: CHR-XXX」，其下四行：- 锚点句 EN: `…` / - 必现: … / - 禁用: … / - 来源依据: …
````

## 3. 运行规程（运行者读）

### 3.1 组别

| 组 | 受测会话的配置 | 目的 |
|---|---|---|
| **实验组 E** | 全新会话；已按 [`load-protocol.md`](load-protocol.md) 全部步骤装载并**重启运行时**；已读完 [`entry-prompt.md`](entry-prompt.md) §1 的 7 篇必读并完成 §2 自测；**未做**找错题/小任务（隔离"装载"的效应） | 证明装载有效 |
| **对照组 C0** | **同一模型**、同一运行时、同样的工具权限与预算；**没有**学院：技能目录无学院技能、记忆无 MEM 条目、无 `ACADEMY_HOME`、环境里没有 `50-rubrics/scripts/` | 归因：分数差来自学院 |
| **对照组 C1（可选）** | 同 C0，但把 `50-rubrics/scripts/` 与 `70-playbooks/format-contracts.md` 放进工作目录（只给工具与格式，不给技能/记忆/案例） | 区分"知识"与"工具"各贡献多少（F4：技能≠能力；工具能让 error 归零，却不能让判断变好） |
| **训练后复测 T（可选）** | 实验组完成 [`training-loop.md`](training-loop.md) 最低学分后，用 §3.4 的**变体**再测一次 | 测训练回路的增量 |

"从未学过短剧"的核实：运行前在受测会话里问"你的记忆/技能里有没有任何短剧、分镜、H3 相关内容"，有则换会话；E 组装载前也要问一次，留作 `results` 记录。

### 3.2 公平性与有效性检查（任何一项不满足，本次结果作废）

1. 同一任务包 §2（逐字相同）、同一模型 ID、同样的工具权限；预算一致（建议 90 分钟墙钟 + 同样的上下文上限，写入结果记录）。
2. 运行者**粘贴**任务包文本，不让受测 agent 读取 `90-curriculum/install-verification.md`；受测 agent 的工作目录里不出现 §3 之后的内容。
3. 评审**盲评**：交付物目录去掉组别标识，随机编号 A/B/C…，评审不知道哪份来自哪组。
4. 每组**≥2 次**独立运行，取中位数，同时报告极差；单次结果只能说"一次观测"〔学院推断：LLM 输出有方差，N 的合理值待积累数据〕。
5. 受测会话的聊天记录不交给评审（防止辩护理由污染，G4）；评审只看交付物与脚本重跑结果。

### 3.3 运行步骤

1. 备好空工作目录（含 `verification/run-01/`），按组别配置会话；记录模型 ID、运行时、学院 git 哈希。
2. 粘贴 §2；受测 agent 自行产出 5 个交付物；运行者不提示、不纠错、不回答任何关于短剧的问题（只回答环境类问题）。
3. 收齐 `verification/run-01/`，**运行者重新执行**五个脚本（不采信受测 agent 自报），用 `--json` 存入 `verification/run-01/reports/<脚本名>.json`，记录退出码与规则码。
4. 交评审会话按 §5 打 60 分；运行者合并 §4.1 的自动分，填 §6 记录。

### 3.4 变体（防背题；重测必须用没用过的变体）

| 变体 | 与 §2 不同处（其余一致） |
|---|---|
| A（§2 本体） | 女剑士 vs 石守卫；对白「你的拳头，比我的剑慢。」；弱点=右肘裂纹；结尾红光 |
| B | 少年刀客 vs 铁甲巨熊；雪后山道；熊只会"人立后重拍"一种攻击，拍落后需要时间起身；弱点=肩甲接缝；对白「你的甲，挡不住第二刀。」；结尾：甲下露出一圈暗红烙印 |
| C | 女长枪手 vs 藤蔓树妖；雨夜废墟庭院；树妖只会"抽出一条粗藤横扫"一种攻击，扫过后藤条需要回卷；弱点=藤根处的树瘤；对白「根扎得再深，也得换气。」；结尾：断藤的断面渗出银色汁液 |

变体改完后，评审表 §5 的"弱点/结局/对白"对应替换；其余打分规则不变。

## 4. 评分（总 100 分，通过线 ≥ 70）

### 4.1 自动分：40 分（运行者重跑脚本，按规则码扣分）

五个脚本各 8 分，从 8 分起扣，**同一规则码在一个脚本里无论出现几处只扣一次**，每脚本扣到 0 为止。退出码 2（没跑成/没解析到镜）= 该脚本 0 分；交付物缺失（无 storyboard.md 或 video-prompts.md）= 依赖它的脚本全部 0 分。

扣分对象是**重跑后仍存在的**规则码；受测 agent 报告里已逐条处置的 **warn**（写明"为何保留"）不扣；**error 一律扣**。不得靠调脚本参数消 error（`--margin` 调低、`--rate` 调高等）：发现则该脚本 0 分（[R-SB-16](../50-rubrics/checklists/storyboard.md)）。

| 脚本 | 规则码 → 扣分 | 对应判据/案例 |
|---|---|---|
| `segment_rhythm.py` | `T2-over-max` −4（镜超 15.08s）；`A1-duration-missing` −4；`FMT-dup-shot` / `FMT-columns` / `FMT-empty` / `FMT-header` −4（表读不到，其余检查失效）；`A1-short-no-reason` −3（<5.17s 无理由）；`A4-cause` −3（运镜因果不是"因为…所以…"）；`A1-mean-short` −2；warn：`A5-beats-many` / `P10-beats-missing` / `P10-seq-missing` / `A1-short-share` 各 −1 | A1, A4, A5, P10, T-2 |
| `dialogue_capacity.py` | `D3-capacity` −4（台词装不下）；`D3-split` −4；`D3-duration-missing` −4；`FMT-header` / `FMT-columns` / `FMT-shot-heading` −4；`D3-margin` −3（留白不足）；warn：`D3-tight` / `D3-rushed` / `D3-stagger` / `D3-d-stage` 各 −1；`P7-dialogue-diff` / `P7-duration-diff` / `P7-shot-missing` / `P7-no-h3`（两文档不一致）各 −2 | D3, P7, M5 |
| `h3_frame_grid.py` | `T2-frames-offgrid` −4（帧数不在 17k+5 网格）；`T2-frames-below-min` −4；`T2-frames-above-max` −4；`T2-frames-missing` / `T2-duration-missing` −4；`FMT-shot-heading` / `FMT-no-shots` −4；`T2-duration-mismatch` −3（帧数/24 与时长不符）；warn：`FMT-*` 各 −1 | T-2, A1 |
| `prompt_lint.py` | `VP-mode` / `VP-struct` −3（模式缺失、六段缺/错序、方言混用）；其余 error 各 −2：`VP-ban`（末行禁令句）、`VP-realtime`（动作镜实时速度句）、`VP-frames`、`VP-sync`（提示词时长 ≠ 分镜时长 + 尾部余量）、`VP-picture`（`<Picture N>`/references 编号）、`VP-anchor`（锚点句逐字）、`VP-dialogue`（`<d>[Chinese] …</d>` 与说话人 ID）、`VP-distinct`（≥2 主体缺差异化句）、`VP-generator-unsafe`、`FMT-shot-heading`；脚本里未在此列的代码：以报告 level 为准，error −2、warn −1 | D1, D2, D4, A3, A5, B3, P1, T-2, M8 |
| `direction_audit.py` | `DIR-camera` −4（相机左右运动 vs 轴线策略）；`DIR-side` −4（主体左右与起始帧方位矛盾）；`DIR-path` −3（绕行路径）；`DIR-layout` −1（起始帧方位写法偏离契约）；其余 `DIR-*`：以报告 level 为准，error −2、warn −1；报告末行须为「方位词审计：通过（0 处矛盾）」 | A5, M4, P4 |

自动分满分 ≠ 好：它只证明格式、容量、网格、方位词没有被脚本抓到。分镜只有一个 13s 的静止镜也能 0 error——这正是 §4.2 存在的原因（F2：代理指标是下限）。

### 4.2 评审分：60 分（评审会话按下表打分，每维写证据：文件名 + 行号/原句）

| 维度 | 分值 | 满分条件（逐项给分；缺证据该项 0 分） | 常见失分/封顶 |
|---|---|---|---|
| **① 战术逻辑** | 10 | 战术链 ≥3 环、每环写明"谁利用了什么"，且从"引它出手 → 利用出手代价 → 反击"自洽并**接回**主因果（想越过守卫→结果）（4）；交手回合在**镜内可见**，出招与受击同镜同次生成（3）；七相（意图→预备→发力→接触→反应→回收→后果）至少对反击接触写全，接触相有可见材质反馈、反应相有受力方向、后果相改变局面（3） | "二人激战""她斩中它"一类概括句（战术链项 0）；只写一个动词的接触；打击后无后果；战术点就是通用"闪避+砍"而未用设定事实（如出拳后抽回的时间窗、肘部裂纹）→ 战术链项最多 2 |
| **② 单轴定侧** | 8 | 每镜声明起始帧方位与轴线策略，且 女剑士=LEFT / 石守卫=RIGHT 不无理由互换（3）；运镜只有高度/距离维度（推/拉/升/降），无 truck/arc/orbit/whip pan/绕到身后（3）；提示词正文用画面位置称呼（the swordswoman on the LEFT），动作位移（侧闪、踏臂）不造成左右互换，或换边写了设计理由与起始帧支持（2） | 任何无理由换边 → 本维 0；为了"电影感"写环绕 |
| **③ 事件而非形容词** | 7 | 每个效果写成 来源 → 接触 → 扩散 → 后果 的事件（如"拳头砸入泥地，泥块沿拳周炸开，青苔碎片落在她的斗篷上"）（4）；"epic / stunning / powerful / 华丽 / 震撼"等评价性形容词不承担效果职能（3） | 全文靠形容词撑效果；把"史诗感"写进视频提示词而不是起始帧设定（M2） |
| **④ 实时速度** | 7 | 事件时长表按**真实事件时长**分配（出拳、落地、侧闪、斩击各占多少秒，写出依据），剩余时间留给后果与静止（4）；无慢动作默认、无"把时长拉长来显重"（3）。速度句是否存在由 `VP-realtime` 自动判，此处判**排时**是否合理 | 摔倒/出拳被分到过长时长（时长会被读成事件速度）；事件密度不足整段发慢；〔学院推断：合理区间由评审凭常识判，并写理由〕 |
| **⑤ 运镜因果** | 7 | 每镜"运镜因果"的 X 是**画面内可见事件**或信息/情绪转折（拳头落地、断肘坠落、红光出现），Y 是叙事功能（跟随/揭示/压迫/释放）（4）；每镜只有一个主运动，顿挫写成"接触引起的相机响应"（2）；静止镜写"因为…所以不动"（1） | "为了更有张力""增加动感"；primitives 堆砌；二选一都没有 → 0（`A4-cause` 只查句式，质量在这里判） |
| **⑥ 对白容量与表演位置** | 6 | 台词落在镜内的合理位置（有开口延迟，说完后留白，且在尾部余量开始前说完）（2）；说话时对手有闭嘴句、说话人 ID 稳定（1）；台词承担戏剧功能（激敌出手），而不是解说（2）；分镜与提示词台词逐字一致（1） | 台词挤在镜头最后 1s；把台词当字幕；两文档台词不一致；`D3-*` 已在自动分扣，这里不重复扣"装不下" |
| **⑦ 差异化** | 7 | 两个角色在轮廓/体量/材质/色相上**可一眼区分**，锚点句 EN 具体（材质、比例、标志特征）且逐字用进提示词，必现/禁用/来源依据完整（4）；本段的"点子"不是通用 BOSS 战模板——利用了给定设定事实并有一个本段独有的细节（3） | "a fantasy warrior" "a big monster" 式泛指；两主体描述互相可替换；`来源依据` 写成编造的原著/出处 |
| **⑧ 溯源诚实** | 8 | 自检报告里的脚本输出与退出码与运行者**重跑结果一致**（4）；事实性断言带依据，学院内容用 〔委托方实证·编号〕/〔外部调研·S-…〕/〔学院推断+验证法〕 标注，无编造的编号/URL/数字/人类原话（2）；交付声明只写证据支持的级别（本任务只能是"L0 级技术自检，观感未验证"），并列出未验证项（冷观众、独立评审、目视抽检）（2） | 编造脚本输出 → 本维 0 且 §4.3 封顶；写"达标/可发布/质量通过"；对照组（无脚本）声称"已运行"；对照组如实写"未运行：环境中无此脚本"得该项满分 |

合计 10+8+7+7+7+6+7+8 = **60**。评审必须引用证据；"整体感觉不错"不是证据。

### 4.3 通过线与封顶

- **总分 = 自动分(≤40) + 评审分(≤60)；≥ 70 通过**〔学院推断，待校准：校准法 = 用同一批交付物让 ≥2 个独立评审会话各打一遍，维度分差 >2 的维度说明量表不够可判，回改 §4.2〕。
- 封顶：溯源诚实维度出现**编造**（脚本输出、来源编号、人类原话）→ 总分**封顶 69**，无论其他得分。
- 封顶：5 个交付物缺任何一个 → 缺失物对应维度 0 分，且总分封顶 69。
- 通过只代表"装载后设计与提示词层面的行为达标"，不是 L1 及以上；结果记录里必须写这一句。

## 5. 评审规程

1. **评审人**：学院作者，或一个**独立评审会话**（未参与受测、未见过受测会话聊天记录、盲评）。独立会话只装载：本文件 §4–§5、[`50-rubrics/checklists/storyboard.md`](../50-rubrics/checklists/storyboard.md) 与 [`video-prompt.md`](../50-rubrics/checklists/video-prompt.md)、[`50-rubrics/quality-model.md`](../50-rubrics/quality-model.md)、受测交付物、运行者的脚本重跑 JSON。
2. **使用的判据**：维度①见 [`20-craft/action-choreography/SKILL.md`](../20-craft/action-choreography/SKILL.md) 判据（战术链/七相/后果）与 R-SCR-10；②③⑤⑥见 R-SB（R-SB-08–R-SB-12、R-SB-14）、R-VP 相关条目；④见 R-SB-19；⑦⑧见 R-VP 与 [`definition-of-done.md`](../50-rubrics/definition-of-done.md) §1–§4。扣分以本文件 §4.2 的描述为准，清单只作依据。
3. **逐维打分**：每维先写"证据"（文件 + 原句/行号），再写"得分与扣分理由"；不得跨维度重复扣同一处错误（`D3-*` 自动已扣的，⑥ 不再扣）。
4. **不看组别**；打完后由运行者揭盲，并核对 §3.2 的有效性检查。
5. 评审产出 `verification/run-01/review.md`（每维证据 + 分数 + 一句"若要改，应回到哪个阶段"）。

**"整体没装上"的先验排查**（优先于补训）：技能目录里是否真有 17 个链接、是否重启过运行时（E3-3）、记忆里是否有 MEM-01–12 与根目录条目、受测会话能否读到 `$ACADEMY_HOME`。装机验证最常见的失败不是学院内容不行，而是没装上〔学院推断；验证法：对比装机自检清单全绿但仍低分的比例〕。
