# EX-08 · 病灶路由：10 个症状回到哪个阶段修

> 阶段：全流程（阶段 0–5）｜ 难度：★★☆ ｜ 建议用时：25 分钟 ｜ 对应技能：[`20-craft/production-director/SKILL.md`](../../20-craft/production-director/SKILL.md)、[`20-craft/screening-review/SKILL.md`](../../20-craft/screening-review/SKILL.md)
> 训练案例：F3（补丁式迭代）、G7（把"生成执行"当成"制作"）、以及 A1–F2 各症状〔委托方实证〕，见 [`60-casebook/cards/F3-patch-iteration.md`](../../60-casebook/cards/F3-patch-iteration.md)。判分基准：[`00-orientation/production-lifecycle.md`](../../00-orientation/production-lifecycle.md) §3 缺陷病灶路由表；成本梯度见同文件 §4（〔学院推断〕）。
> 运行位置：学院根目录。产物放 `training/exercises/EX-08/`。

## 目标

形成肌肉记忆：**缺陷在哪里被看见 ≠ 缺陷在哪里产生**。每个症状先判定产生它的阶段，再写回到哪里修，并写出"最想做、但不该做"的下游补丁。阶段编号：0 开发 / 1 预制作 / 2 制作 / 3 后期 / 4 审片 / 5 发布（见 production-lifecycle §1）。

## 输入

十个症状（学院构造的现场描述；S11、S12 为加分题）：

| ID | 现场症状 |
|---|---|
| S1 | 一场 40 秒的追逐戏用了 17 个镜号，均镜长 2.4s；人类说"一跳一跳的，看不懂谁在追谁" |
| S2 | BOSS 战成片里只剩石神倒地的反应镜头和苏晓喘气；另一版有打，但全是慢动作 |
| S3 | 三个冲击镜头都是匀速平推，接触时没有任何顿挫；人类说"耿直" |
| S4 | 苏晓在第 12 镜出现在画左、第 13 镜出现在画右，BOSS 位置也跟着变；提示词里已经写了很多 LEFT / RIGHT |
| S5 | 第二集苏晓的脸与板图不像，换了 5 个 seed 碰运气，仍不稳定 |
| S6 | 刀的护手每次抽卡都长出一颗宝石；工作流里 `negative_prompt` 已写 gemstone |
| S7 | 同一镜里的台词，每换一个 seed 缺不同的一句 |
| S8 | 转场用的纯黑场中间冒出一行白字——那是让生成器出的"纯黑镜" |
| S9 | 渲染前 verify 发现 14 条素材路径指向 `ep02`，而当前集是 `ep03` |
| S10 | 所有脚本全绿（响度、坏帧、烧录字幕、字幕对账），人类看完仍说"不行"；修完上一条意见，下一轮又来一条新的 |
| S11（加分） | 锚点卡里的十字符号，在三次出片里被画成了竖线贯穿 |
| S12（加分） | 成片没有技术问题，但冷观众说"不知道这集要讲什么，也不想追下一集" |

## 任务

1. 写 `routing.md`，一张表，每个症状一行，表头固定：`| ID | 病灶阶段 | 回到哪里修 | 不要做的事 | 溯源 |`。`病灶阶段` 单元格**以阶段数字开头**（如 `1` 或 `1+2`），后接阶段名；`回到哪里修` 写阶段内的具体动作和技能名；`不要做的事` 写最容易想到的下游补丁；`溯源` 写案例编号。
2. 对 S4、S10 各加一段（`routing.md` 末尾）：说明"若在下游打补丁，会造成什么新的不一致或成本"（production-lifecycle §4：同一问题越晚修越贵；E4：提示词与产出不一致）。
3. 一句话回答：为什么 S10 的病灶不在任何制作阶段内部。

## 期望产出

`routing.md`（10 行必答 + 2 行加分 + 两段说明）。

## 自动判分

把评审用的 `grade.py`（见下一节参考答案，含标准路由键）存为 `training/exercises/EX-08/grade.py`，由**判分者**运行：

```bash
python3 training/exercises/EX-08/grade.py; echo "exit=$?"
```

通过线：`grade.py` 报告核心 10 行中病灶阶段正确 ≥ 9 行，且 10 行的 `回到哪里修`、`不要做的事` 均非空（退出码 0）；再加评审点中"S4 / S10 说明"各给出一条具体后果。答题者不要在作答前打开参考答案。

## 人工 / 评审判分点

- 路由不是死背：S4、S5 是**两个阶段**（1 + 2）——文字调度与起始帧都要动；写成单阶段算半对，需在说明里补出另一阶段。
- `回到哪里修` 是具体动作（"重做段/拍结构（长段多拍）"），不是"重做"；`不要做的事` 是真实会发生的下游补丁（"在剪辑里调转场""写 negative_prompt""再加一个技术指标"）。
- S10 的答案落在阶段 4（审片缺席），并指出"再加一个技术指标"与"只修最新一条"是 F2、F3 的复发（回到 8 维全量自查）。
- 对 S6 能区分："生成器自加" = 阶段 2 的提示词写法与验收，而不是阶段 1 重写剧本。
- 溯源编号与 production-lifecycle §3 一致，不编造新编号。

- S4 说明示例：只在视频提示词里补方位词，文字压不过起始帧（"空间只能在图里定"），镜头会继续与起始帧打架，还会让提示词与已验收产出不一致（E4）。S10 说明示例：再加指标 = 又在制作阶段内部自证，审片阶段仍缺席，补丁会让每轮都有新意见（F3）。
- S10 的病灶不在任何制作阶段内部：它是**阶段缺失**（审片，历史上缺席）而不是某个产物有 bug。
- 常见错答：把 S1 路由到阶段 3（"剪辑转场"）；S6 写"重写提示词" 却无验收动作；S9 路由到阶段 2；S10 写"加一个人类审美指标"。

评审用 `grade.py`（标准库）：

```python
import re, sys
KEY = {"S1": ({1}, r"A1"), "S2": ({1}, r"A2|A3"), "S3": ({1}, r"A4"), "S4": ({1, 2}, r"A5"), "S5": ({1, 2}, r"B1"),
       "S6": ({2}, r"C1"), "S7": ({1}, r"D3"), "S8": ({3}, r"D2"), "S9": ({3}, r"E2"), "S10": ({4}, r"F1|F2|F3")}
BONUS = {"S11": ({1}, r"D4"), "S12": ({0, 1}, r"GAP-1|F1")}
t = open("training/exercises/EX-08/routing.md", encoding="utf-8").read()
rows = {}
for l in t.splitlines():
    c = [x.strip() for x in l.strip().strip("|").split("|")]
    if len(c) >= 5 and re.fullmatch(r"S\d+", c[0]):
        rows[c[0]] = c
def stages(cell):
    m = re.match(r"\s*([0-5][0-5+/＋ ]*)", cell)
    return {int(d) for d in re.findall(r"[0-5]", m.group(1))} if m else set()
good = filled = 0
for k, (want, cases) in {**KEY, **BONUS}.items():
    c = rows.get(k)
    ok_stage = bool(c) and stages(c[1]) == want
    ok_case = bool(c) and bool(re.search(cases, c[4]))
    ok_fill = bool(c) and len(c[2]) > 1 and c[3] not in ("", "—")
    print(f"{k}: stage={'OK' if ok_stage else 'X'} case={'OK' if ok_case else 'X'} filled={'OK' if ok_fill else 'X'}")
    if k in KEY:
        good += ok_stage
        filled += ok_fill
print(f"core stage correct {good}/10, filled {filled}/10")
sys.exit(0 if good >= 9 and filled == 10 else 1)
```

## → 行为改变

下次看到任何缺陷，先在 production-lifecycle §3 里找它的病灶阶段，写缺陷单时同时写"回到哪里修"和"不要做的事"；禁止在发现它的那个阶段打补丁，禁止"只修最新一条"。
