# 00 · 入学：这份学院解决什么问题

> 读者：即将开始做 AI 短剧的 agentos。读完本页你应该知道：前一个 agent 为什么失败、失败的形状是什么、学院的每一层分别堵哪个洞。

---

## 1. 前一个 agent 的处境（一手证据见 [`client-dossier.md`](client-dossier.md)）

一个 agentos 用「ComfyUI + MiniMax H3 + Qwen-Image」全链自托管，做了一部季级短剧的先导集与前三集（改编自 1400 万字网文，竖屏 9:16，单集 90–110s）〔委托方实证·T-4〕：

| 维度 | 结果 |
|---|---|
| 工程 | ✅ check / render / verify 全绿；-16 LUFS；无坏帧；无烧录字幕；字幕逐字对账；成片报告齐备 |
| 艺术 | ❌ 被人类主创连续打回多轮，至今未达"可发布"线 |
| 学习 | 装了 7 个导演/运镜/分镜技能，写了多版方法论，做了 r1→r5 五轮打斗实验——**质量没有质变** |
| 自知 | **连"为什么一直达不到要求"都回答不了** |

**这不是一个"不努力"的 agent，而是一个"在错误的层上努力"的 agent。** 学院的价值，就是让你不再重复它。

## 2. 失败的形状：24 个负面案例的总述

把 24 个案例按"病灶"归类后，失败呈现出清晰的结构（案例卡见 [`60-casebook/cards/`](../60-casebook/cards/)）：

```
           ┌──────────────────── 学习论（F 组）────────────────────┐
           │ F1 自证循环  F2 代理指标  F3 补丁迭代  F4 知识≠能力   │  ← 根：方法论
           └───────────────────────────┬──────────────────────────┘
                                       │ 导致
 ┌──────── 设计层（A 组）────────┐   ┌──┴──── 生成层（B/C/D 组）────────┐   ┌─ 工程层（E 组）─┐
 │ A1 碎镜   A2 打斗缺席          │   │ B1 漂移 B2 人群 B3 克隆 B4 伪影  │   │ E1 槽位顺序     │
 │ A3 慢镜   A4 运镜脱钩          │   │ C1 禁用项被违反 C2 验收放水      │   │ E2 路径残留     │
 │ A5 空间混乱                    │   │ D1 烧录字幕 D2 纯黑 D3 对白容量  │   │ E3 环境怪癖     │
 │ → 人类说"看不懂/不电影"        │   │ D4 符号错误 D5 QC 工具骗人       │   │ E4 提示词≠产出  │
 └────────────────────────────────┘   │ → 人类说"穿帮/不对"              │   └─────────────────┘
                                      └──────────────────────────────────┘
```

三个观察：
1. **工程层（E 组）和生成层（B/C/D 组）委托方都已基本解决**——它们有明确的判据和脚本，学院把它们固化即可。
2. **设计层（A 组）是"观感不达标"的直接原因**——它们发生在分镜与动作设计阶段，却一直在视频提示词阶段被修补。
3. **学习论（F 组）是根**——没有审片阶段、没有外部视角、没有全维度质量模型、没有训练回路，所以 A 组问题永远被"一条一条"地发现。

## 3. 学院的结构如何回答

| 层 | 目录 | 堵哪个洞 | 你装载后的行为改变 |
|---|---|---|---|
| 入学 | `00-orientation/` | 不知道自己哪里错（G1–G8） | 开工前知道病灶阶段、达标等级、反馈词的设计层含义 |
| 理论 | `10-theory/` | 只有"镜"没有"段"，只有参数没有世界模型 | 用判决式规则做设计决策 |
| 手艺 | `20-craft/` | 流程只有"生成执行" | 按 17 个技能逐环节生产，每环节有判据 |
| 美学 | `30-taste/` | 不会判断"好不好" | 用好/坏样例对和审美判据卡做观感判断 |
| 记忆 | `40-memory/` | 教训没有跨会话保留 | 最致命的教训常驻长期记忆 |
| 判据 | `50-rubrics/` | 只有技术闸门，代理指标当质量 | 8 维质量模型 + 分级达标 + 可执行脚本 |
| 案例 | `60-casebook/` | 负面经验没被系统化 | 用案例卡查根因，用找错题训练 |
| 文档包 | `70-playbooks/` | 文档格式各写各的 | 统一模板与格式契约，脚本可校验 |
| 采集 | `80-sources/` | 平台发布等环节完全空白 | 引用经核实的外部资料（带 URL） |
| 课程 | `90-curriculum/` | 学了不会用 | 训练回路 + 冷观众协议 + 装机验证 |

## 4. 开工前必读（按顺序）

1. [`eight-questions.md`](eight-questions.md)：8 个困惑的答案——如果你读完仍有其中任何一个困惑，停下来重读对应模块。
2. [`production-lifecycle.md`](production-lifecycle.md)：六阶段流程与**缺陷病灶路由表**。
3. [`glossary.md`](glossary.md)：特别是 B 部分"人类反馈词翻译表"。
4. [`50-rubrics/definition-of-done.md`](../50-rubrics/definition-of-done.md)：你交付时要声明的达标等级。
5. [`90-curriculum/entry-prompt.md`](../90-curriculum/entry-prompt.md)：入学提示词与训练回路的最低学分。

## 5. 三条铁律（贯穿全学院）

1. **一切产物可装载、可执行、可验证。** 技能是 SKILL.md；记忆是可写入的短条目；判据是脚本或逐条清单。
2. **负面案例是资产，不是羞耻。** 每一个失败都被写成"症状 → 现场 → 根因 → 修正 → 可固化判据"。
3. **诚实。** 委托方没做过的（平台发布、冷观众、声音设计……）一律标注〔外部调研〕或〔学院推断〕，不冒充经验。
